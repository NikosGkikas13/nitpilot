# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Public docs at `/docs` inside the existing web app, in nitpilot.dev's look, written as Markdown files, and the landing page's Docs link pointing there.

**Architecture:** New lazy route `apps/web/src/routes/Docs/` mounted outside `<Home>` (no auth, no socket). Pages are `.md` files bundled with `import.meta.glob(…, { query: '?raw' })`, turned into HTML by `marked`, and listed in one TypeScript registry that drives the sidebar, prev/next, search and the link check. The server needs no change: `/docs` is not a server path, so `spaRoutes` already answers it with `index.html`.

**Tech Stack:** React 19, react-router 8, Vite 8, CSS modules + `tokens.css`, Vitest + Testing Library, Playwright, `marked@18.1.1` (new, pinned exactly).

**Spec:** `docs/superpowers/specs/2026-10-29-docs-site-design.md`

## Global Constraints

- Branch `docs-site`, cut from `main` at 21cfe5e (Copilot support merged in PR #10); work in the worktree `../.nitpilot-scratch/docs-site`. Ships with Copilot support in v0.1.3.
- No new site, build tool or domain. One new dependency only: `marked`, exact version `18.1.1`.
- Colors, radii, fonts only from `apps/web/src/styles/tokens.css`; light and dark both work; reuse `Wordmark`, `ThemeToggle`, `SIGN_IN_URL` (from `routes/Landing/Landing.tsx`).
- Docs are their own lazy chunk; the main bundle must not import anything under `routes/Docs/`.
- No `/api` call and no WebSocket on any `/docs` page.
- At 375px wide: 16px side gutters, no horizontal page scroll (code blocks and tables scroll inside themselves).
- Page title format: `<Page title> · Nitpilot docs`.
- Text says "nitpilot.dev" everywhere; the README and `docs/*.md` source files are not changed.
- Internal material never becomes a docs page: `hosting.md`, `releasing.md`, `superpowers/`, `design/`, `launch/`, `acceptance/`, `why/`.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A broken link between pages** (a renamed slug, a link copied from the README like `docs/self-hosting.md`) should fail a test, not reach a visitor. → Task 1 Step 1 `links` test; content tasks run it.
2. **An unknown address** such as `/docs/quickstrat` should show "Page not found" inside the docs layout with a link to Introduction, not the app's empty inbox pane. → Task 1 Step 1.
3. **Clicking a link to another docs page** should switch pages without reloading the whole app, and `#heading` links should scroll to that heading. → Task 1 Step 1 and Task 2 Step 1.
4. **A phone-width visitor** must reach the page list (Menu button) and never scroll sideways because of a long command. → Task 2 Step 1 and Task 4's Playwright check.
5. **Search with no match or an empty query** should say "No results" / show nothing, never throw. → Task 3 Step 1.

**Interfaces:**
- Produces (`pages.ts`):
  - `export const DOC_GROUPS = ['Get started', 'Guides', 'Reference', 'Help', 'Under the hood'] as const; export type DocGroup = (typeof DOC_GROUPS)[number];`
  - `export type DocPage = { slug: string; title: string; group: DocGroup };`
  - `export const DOC_PAGES: DocPage[]` — in sidebar order. Task 1 lists only `{ slug: 'introduction', title: 'Introduction', group: 'Get started' }`; content tasks append.
  - `export function findPage(slug: string): DocPage | undefined`
  - `export function pageSource(slug: string): string | undefined` — from `import.meta.glob('./pages/*.md', { query: '?raw', import: 'default', eager: true })`.
  - `export function neighbours(slug: string): { prev?: DocPage; next?: DocPage }` — previous/next in `DOC_PAGES` order.
- Produces (`markdown.ts`):
  - `export type Heading = { id: string; text: string; depth: 2 | 3 };`
  - `export function slugify(text: string): string` — lower-case, non-alphanumerics to `-`, trimmed of `-`.
  - `export function renderMarkdown(source: string): { title: string; html: string; headings: Heading[] }` — `title` is the first `# ` line (removed from `html`; the layout renders it as `<h1>`). `##`/`###` get `id={slugify(text)}` (a repeat gets `-2`, `-3`). Each fenced code block renders as `<div class="code"><button type="button" data-copy>Copy</button><pre><code>…</code></pre></div>`. Use a `new Marked()` instance with a custom renderer, not the global `marked`.
- Produces (`Docs.tsx`): `export function Docs()` — the route element for both `docs` and `docs/:slug` (no slug = `introduction`).

- A query matching only a heading returns that heading's `id`.
